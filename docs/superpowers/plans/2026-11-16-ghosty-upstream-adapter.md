# Ghosty upstream connection

Goal: connect registered demos and the existing NoName raw logs to the real upstream decoder, matcher and concussion estimator without a fork or extra raw downloads/copies.

Architecture: a separately managed official Git checkout per commit under `/opt/noname-hltv-tools/releases/<sha>`, atomically selected by `active.json`. Our Python/Node adapter lives in this website repository and imports the untouched upstream APIs. Updates explicitly fetch, run upstream compatibility checks and switch the pin; startup never follows a moving branch automatically. Old releases support rollback.

First connected capability: authenticated admin queues a demo for a bounded background worker. The worker verifies original checksums, decodes with `goldsrc_demo.Demo`/`demo_viewer.export_demo`, checks both existing parser logs using `server_log.align_log`, requires exactly one accepted pairing and uses upstream `web/conc.js` for pause-aware estimated windows. These are ordinary gameplay observations, not anomaly detections or proof of cheating. Existing anti-cheat analysis status remains unsupported; no Discord anomaly alerts are fabricated. Private run results show revision, matched round/hash, alignment evidence, player windows and limitations.

Safety: disabled by default, no public upstream HTTP server/proxy or filesystem endpoints, original sources read-only, temporary decoded data private and bounded, one queued job at a time, resource/time/output limits, hold on queued/processing/failed runs, explicit retry. Jobs/results persist in SQLite independently of analysis/review/file states. Missing/ambiguous pairing is a failure; zero supported results never becomes a clean verdict.

Tasks: upstream release manager/compatibility pin; bounded thin Python decoder/matcher and Node conc bridge; durable run/hold/API/worker integration; admin controls/results; configuration and rollout/update/rollback docs. Continue the user-authorized verification with targeted tests and upstream regression checks. Real-server sample validation needs execution on the user's host because its demos/logs are not present locally. Hosted 3D playback, game assets and weapon/hitbox comparisons are a later capability; do not expose the upstream localhost application directly.

Implemented and locally verified: 24 targeted registry/API/worker tests passed; official pinned upstream Python matcher and Node concussion transport probes plus its three regression scripts passed through the updater. Authenticated browser checks covered queuing, retained holds, completed-result rendering, CSP and desktop/mobile layouts. Independent review prompted whole-process Linux memory enforcement, Buffer views without a large duplicate allocation, bounded section validation and scoped orphan scratch recovery. Linux systemd enforcement and actual server demo/log matching remain rollout checks. Features remain disabled by default.
